# 藏经阁目录结构设计（方案二：层级分类 + 独立路由侧边栏）

> 定位：轻量级个人导航，只收录园主高频使用或具有长期学习价值的资源。
> 层级铁律：一级模块（独立路由页） + 二级子类（页内锚点），深度 ≤ 2，不允更深。
> 本文只定骨架，不收录具体链接；链接由园主填充、Agent 按 §五 规则长期维护。

## 一、总体结构

- `/nav/`：总览枢纽页——保留现有居中大搜索与卡片预览弹窗，展示各模块精选与快捷入口。
- 五大内容模块 + 园内藏品，各自独立路由页，侧边栏常驻切换。
- 园内藏品为站内合集入口，不计入数量红线（随 `collectionsConfig` 自动增减）。

交互规范：

- PC 端：侧栏固定；一级模块为路由链接，当前路由高亮；其下二级子类默认展开，点击平滑滚动至锚点（`scroll-margin-top: 4.5rem` 预留导航栏）。
- 路由全部收敛在 `/nav/` 前缀下，现有 `isNavSitesPage()` 正则 `/\/nav(\/|$)/` 天然覆盖子路由，wide 单列布局无需改判定逻辑。
- 移动端：侧栏默认隐藏，汉堡按钮呼出（覆盖层模式），点击子类后自动收起。
- 搜索：枢纽页大搜索保留，范围覆盖全部模块（配置驱动，按模块过滤可选）。

## 五、治理与维护规则（Agent 长期执行）

1. **数据源 SSOT**：全部资源登记于 `src/config/navSitesConfig.ts`，按路由分模块组织；页面只渲染配置，不硬编码。
2. **新增**：按互斥边界自动归类；同一资源只入一个子类，拿不准时归「主要用途」所在子类；推荐排序置顶名额每子类 ≤ 3。
3. **删除**：每季度巡检一次链接有效性，失效或长期不用的提议移除，经园主确认后执行。
4. **重构红线**：子类链接 < 3 个持续一个巡检周期 → 提议并入相近子类；> 15 个 → 提议细分新子类（仍保持两层）。
5. **「备用」标记**：仅限 5.1 在线影视等高失效场景，同站多镜像共享一个名额，主链接失效时自动顶替。
6. **命名规范**：一级「序号 + 模块名」（一、学习进修），二级「数字编号 + 子类名」（1.1 学习平台）；路由与锚点 id 用英文 kebab-case，与映射表一致。

## 六、实施提示（后续编码轮次）

- 复用现有 `SiteCard.astro`（外链卡 + 合集卡）与预览弹窗逻辑，按模块拆页只动路由层。
- 侧栏组件为 `/nav/` 页族共享 island；激活态由 URL 驱动，避免 swup 静态 DOM 残留问题（同侧栏隐藏机制的既有教训）。
