# 渠道 3：无材料调研（广搜 + 自动配图）

用户只给题目或说「帮我查 / 没有参考只要调研」。没有进料正文，也没有现成配图。  
默认**并发**（园主常先开 Cursor Multitask / `Task` 子代理），禁止单线程「搜一下网页就写」。

## 实时现况：先 Ask Grok

定价、订阅档、模型对比、政策变更、当天热点：本地 Tavily / Exa / Bocha 容易过时且烧 MCP。先走全局 skill `ask-grok`（grok.com 专家模式），用户把回复贴回后再当**渠道 2 粘贴**（`paste_kind: grok`）。本渠并发广搜留给「需要视频 / 论坛 / 配图、且不是强时效口径」的题目。

## 并行拆岗（父代理汇总）

```text
┌─ Web          官方文档、发布说明、Changelog、高质量博文
├─ Video        B 站 / YouTube：标题、UP、口播要点、置顶评论里的踩坑（不转载字幕全文、不下整片）
├─ Voice        行业大佬：X/Twitter、博客、Newsletter、会议 slides、GitHub Discussion
├─ Practice     使用心得：linux.do、V2EX、少数派、即刻、Reddit、HN；技巧贴与踩坑
└─ Images       场景配图检索（与上列并行）→ 见 images.md
```

父代理给出题目与 Theme 猜测；子代理各交「可带走的点 + 链接 + 日期」。汇总后再提炼成一篇笔记，不要四份并列稿。

## 搜索渠道（最低清单）

每一岗至少留下**可点击的一级来源**。搜不到就写「未找到」，禁止编造名言。

| 岗 | 去哪 | 要什么 |
|----|------|--------|
| 官方 | 产品 docs、GitHub README/Releases、状态页 | 版本号、限制、官方口径；写核对日 |
| 视频 | B 站搜索、YouTube；必要时用站内摘要/章节 | UP、发布日、可核对的操作步骤；视频只当片单链接 |
| 大佬 | 已知维护者 / 核心贡献者的博客与 X | 原话或可引用段落；标注账号与日期 |
| 心得 | linux.do、V2EX、Reddit、HN、少数派 | 「这么用才稳」与「这坑我踩过」；区分个例与共识 |
| 新闻 | 仅作线索，事实回官方或仓库 | 不要把转载稿当一级证据 |

工具：WebSearch / 浏览器 / `curl.exe` 公开页。不要上 RSS MCP 凑数。不要为了「像调研」去扫与题目无关的热榜。

## 证据纪律

- 数字、版本、「官方承认」必须能指回链接；否则写「作者称 / 待核实」。
- 口播与论坛帖默认当**经验**，不是规范。
- 中英源都要：只搜中文社区或只搜英文官方都算漏岗。
- 时效：默认近 12 个月；更早的标明年份。

## 自动配图（本渠必做）

渠道 3 **没有**随文配图，必须检索匹配，流程见 [`images.md`](images.md)。

按笔记小节列「这一节读者在看什么场景」→ 搜对应画面（产品 UI、架构示意图、官方 OG、操作截图）→ 上 R2 → 插入正文。  
装饰性风景、无关科技库存图不要。GIF 仅当用户在本轮明确要动图。

检索仍空：降优先级走 `firefly-minimax-media`（先 `check_quota.py`），并在交付里写明「检索未命中，已生图 / 未生图原因」。

## 落盘

`source: research`。写入 `D:\OneDrive\Desktop\Notes\threetwoa_ob` 已有主题夹（优先 `Agentic Coding/`）。关键出处写在笔记里（链接+日期），不要另造空 `source/` 目录除非用户给了长文原料。不要写 Knowledge。

交接 output 时说明：这是调研稿，图已是 R2 或仍待 MiniMax；理想稿在 vault。
